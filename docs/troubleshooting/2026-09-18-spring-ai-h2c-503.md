# Spring AI 요청이 503으로 끝난 h2c 업그레이드 호환성 문제

## 결론

PostForge의 JDK 21 HTTP 클라이언트가 평문 HTTP 게이트웨이에 HTTP/2 업그레이드(h2c)를 시도했고, Uvicorn 0.40.0의 `httptools` 경로가 이 요청을 정상 처리하지 못했다. 그 결과 게이트웨이는 요청 본문을 받지 못한 것으로 판단해 422를 반환했고, 백엔드는 이를 `EXTERNAL_SERVICE_UNAVAILABLE` 503으로 변환했다.

이는 HTTP/2나 LLM API 전체가 호환되지 않는다는 뜻이 아니다. 현재의 **JDK 21 클라이언트 + 평문 HTTP + Uvicorn 0.40.0 `httptools`** 조합에서 h2c 업그레이드 요청이 실패한 사례다. HTTP/2를 지원하는 서버·프록시와 TLS/ALPN으로 협상하는 구성 등에서는 HTTP/2로 LLM API를 호출할 수 있다. 예를 들어 클라이언트→프록시는 HTTP/2, 프록시→현재 게이트웨이는 HTTP/1.1로 구성할 수 있다.

## 증상과 추적

2026-09-18 04:06:51 UTC, `/api/ai/chat` 요청 `requestId=757f896f-7533-488a-951e-d988aef19b4a`가 503으로 종료됐다.

1. Spring AI 재시도 로그에서 게이트웨이 응답 `422`와 `body` 필수 필드 누락을 확인했다.
2. 호출 스택은 `OpenAiApi.embeddings` → `PgVectorStore.getQueryEmbedding` → [`PgVectorSearchAdapter.searchSimilar`](../../ai/src/main/java/dev/iamrat/ai/search/infrastructure/vector/PgVectorSearchAdapter.java) → [`ChatService.chat`](../../ai/src/main/java/dev/iamrat/ai/chat/application/ChatService.java) 순서였다.
3. `ChatService`는 문서 검색을 답변 생성보다 먼저 실행하므로 텍스트 생성에는 도달하지 않았다.
4. `PgVectorSearchAdapter`가 원본 `RuntimeException`을 `EXTERNAL_SERVICE_UNAVAILABLE`로 변환하고, [`CommonErrorCode`](../../core/src/main/java/dev/iamrat/core/global/error/CommonErrorCode.java)의 `SERVICE_UNAVAILABLE` 정의와 [`ExceptionResponseHandler`](../../support/src/main/java/dev/iamrat/support/web/ExceptionResponseHandler.java)에 따라 클라이언트에는 503이 반환됐다.
5. 같은 시각 게이트웨이 로그에 `Unsupported upgrade request.`가 기록됐다.

즉, 응답 코드는 두 구간에서 달랐다.

```text
LLM 게이트웨이 → PostForge: 422 Missing request body
PostForge       → API 클라이언트: 503 EXTERNAL_SERVICE_UNAVAILABLE
```

## 격리 재현

실행 중인 게이트웨이의 로컬 이미지 ID `sha256:987653f332c5d1a98728ea5223b5c5860b04f9d8e14fb3d6aabc69fae93ff24b`로 임시 컨테이너를 만들었다. 기존 8088과 충돌하지 않도록 loopback의 임의 포트를 사용하고 인증은 진단용 토큰으로 교체했다. Ollama는 기존 인스턴스를 공유했으므로 운영 전체의 완전한 복제는 아니며, 게이트웨이 프로세스와 포트만 분리한 재현이다.

JDK 21 프로브에서 주소, 인증, JSON 본문, `bge-m3`, 1024차원은 그대로 두고 HTTP 버전 선호도와 본문 framing만 바꿨다.

```json
{"model":"bge-m3","input":["diagnostic test"],"dimensions":1024}
```

임시 컨테이너 포트는 `-p 127.0.0.1::8088`로 배정했다. 프로브는
`HttpClient.Builder.version()`에 `HTTP_1_1`과 `HTTP_2`를 각각 지정하고,
`BodyPublishers.ofByteArray()`와 `BodyPublishers.ofInputStream()`으로 길이를 아는 본문과
길이를 모르는 스트리밍 본문을 비교했다. 후자는 HTTP/1.1 전송 시 chunked가 된다.
`HTTP_2` 우선 설정이라고 최초 요청이 이미 HTTP/2라는 뜻은 아니다. 이번 평문 연결에서는
HTTP/1.1 요청의 h2c 업그레이드 시도가 문제였으며, 게이트웨이 접근 로그에도 HTTP/1.1로 기록됐다.

| HTTP 설정 | 본문 framing | 결과 |
| --- | --- | --- |
| HTTP/1.1 고정 | Content-Length | 200 |
| HTTP/1.1 고정 | chunked | 200 |
| HTTP/2 우선 | Content-Length | 422, body missing |
| HTTP/2 우선 | chunked | 422, body missing |

본문 framing과 무관하게 HTTP/2 우선 요청에서만 운영과 같은 422 및 업그레이드 경고가 재현됐다. JDK는 버전을 지정하지 않으면 HTTP/2를 우선하고 요청마다 업그레이드를 시도한다. 자세한 동작은 [JDK 21 `HttpClient.Builder.version`](https://docs.oracle.com/en/java/javase/21/docs/api/java.net.http/java/net/http/HttpClient.Builder.html#version(java.net.http.HttpClient.Version))과 [Uvicorn 0.40.0 `httptools_impl.py`](https://github.com/encode/uvicorn/blob/9ff60042a53cd1bbfd5580ab0a91ea2d1d8f2f8c/uvicorn/protocols/http/httptools_impl.py)를 참고한다.

## 수정

채팅과 임베딩이 공유하는 [`LlmConfig.timeoutRequestFactory`](../../ai/src/main/java/dev/iamrat/ai/support/infrastructure/llm/LlmConfig.java)에서 JDK 클라이언트를 HTTP/1.1로 고정한다.

```java
HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_1_1)
    .connectTimeout(connectTimeout)
    .build();
```

이 변경은 PostForge에서 LLM 게이트웨이로 나가는 연결에만 적용된다. 모델 `qwen3:8b`, 임베딩 모델 `bge-m3`, 임베딩 1024차원 설정은 바꾸지 않는다.

## 검증

회귀 테스트는 로컬 HTTP 서버로 실제 채팅·임베딩 요청을 각각 보내 두 요청이 모두 HTTP/1.1이며 `Upgrade` 헤더가 없음을 검사한다.

```bash
./gradlew :ai:test \
  :app:test \
  --tests dev.iamrat.app.LlmGatewayConfigurationTest \
  --tests dev.iamrat.app.LlmProviderSwitchingTest \
  :app:bootJar \
  --console=plain
```

수정 전 회귀 테스트는 채팅과 임베딩 요청에서 실제 `Upgrade: h2c` 헤더 두 건을 감지해 실패했다. HTTP/1.1 고정 후 위 명령은 AI 테스트 63건과 앱 테스트 6건, `bootJar`를 모두 성공했다. 테스트는 실제 `LlmConfig`와 OpenAI 모델을 loopback JDK `HttpServer`에 연결해 채팅·임베딩 응답 및 두 요청의 `Upgrade` 헤더 부재를 검증한다.

운영 게이트웨이와 Ollama를 포함한 전체 경로 검증은 아직 남아 있다. 변경된 백엔드 이미지를 재빌드·배포한 뒤 실제 `/api/ai/chat` 호출 성공, 게이트웨이의 업그레이드 경고 소멸, 임베딩과 채팅 응답을 확인해야 완료된다.
