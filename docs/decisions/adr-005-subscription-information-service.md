# ADR-005 뉴스 자동 게시와 향후 메일 구독

상태: **Accepted / Amended 2026-09-08** (최초 결정: 2026-08-20)

## 변경 기록

- **2026-08-20**: 메일 구독 중심의 제품 방향과 `digest_subscriptions`·`digest_deliveries`를 사용하는 구독·발송 및 중복 방지 설계를 결정했다. 이 메일 기능은 구현되지 않았다.
- **2026-09-08**: 제품 범위를 다시 확인해 뉴스 자동 게시와 06시 데일리 게시를 현재 범위로 정하고, 메일 구독은 후속 확장으로 옮겼다. 기존 구독·발송 스키마와 재시도·중복 방지 설계는 구현 시점에 재검토한다.

## 현재 제품 정의

PostForge의 현재 제품 정의는 다음과 같다.

> 뉴스를 수집해 분야별로 분류하고 LLM으로 가공한 초안을 자동 게시하며, 매일 06:00(Asia/Seoul)에 전날 뉴스를 종합한 데일리 포스트를 자동 게시하는 정보 서비스.

메일 구독은 이 콘텐츠를 전달할 향후 채널이다. 현재 구현된 기능이나 보장으로 취급하지 않는다. 이 결정은 ADR-004의 구매 판단 중심 제품 정의와 가격 기능 부활 조건을 대체한다.

## 배경

- 자동 수집·게시 파이프라인은 사용자 수와 무관하게 콘텐츠를 축적할 수 있다.
- 가격 비교·특가·구매 판단은 지속 가능한 데이터 소스가 없고 현재 정보 제공 목표와도 맞지 않는다.
- 공개 게시글은 검색과 재방문을 위한 아카이브가 되며, 댓글·좋아요·AI 채팅은 보조 기능으로 남는다.

## 현재 결정과 구현

현재 개별 자동 게시의 구현 범위는 출시 뉴스다.

1. 운영자가 관리하는 `tracked_keywords`를 기준으로 뉴스를 수집한다.
2. 수집 결과를 게시 적격성 정책으로 거르고 수집 키워드 또는 수동 요청에 지정된 분야를 `board_category`에 기록한다. 현재 분야 판정은 LLM이 수행하지 않는다.
3. LLM이 통과한 뉴스의 글 초안을 만들고 `posts.category=PRODUCT_LAUNCH_NEWS`로 자동 게시한다. 개별 뉴스 게시글의 원문 출처는 `post_reference_links`에 함께 저장한다.
4. 매일 06:00(Asia/Seoul)에 전날 게시된 `PRODUCT_LAUNCH_NEWS`의 제목·요약을 분야별로 종합해 `posts.category=DAILY_DIGEST`로 자동 게시한다.

기본 실행 시각은 `ingest.news.digest.cron`의 `0 0 6 * * *`이며 스케줄 시간대는 `Asia/Seoul`이다. 수동·backfill 경로와 정확한 API 계약은 [API 명세의 자동 게시 스케줄](../api/README.md#자동-게시-스케줄)을 따른다.

`LaunchNewsEligibilityPolicy`의 광고성 표현 필터(특가·쿠폰·할인·최저가·공동구매)는 가격 기능이 아니다. 광고성 기사를 정보 게시물에서 제외하기 위한 현재 수집 정책이므로 유지한다.

## 향후 범위: 메일 구독

- 사용자가 관심 분야의 데일리 포스트를 메일로 받아보는 기능을 검토한다.
- 구독 API, 구독·발송 schema, 발송 재시도와 중복 방지 방식은 아직 구현되거나 확정되지 않았다.
- 구현을 시작할 때 수신 동의·해지, 개인정보 보존, 발송 평판, 멱등성과 장애 복구 요구를 별도 설계한다.

구독이 도입되더라도 수집 대상은 운영자의 `tracked_keywords`, 콘텐츠 분류는 `board_category`가 담당한다. 구독자 수가 뉴스 수집량이나 LLM 초안 생성량을 직접 늘리지 않는 방향을 유지한다.

## 범위에서 제외

- 가격 비교, 최저가, 특가 판정, 구매 판단
- 키워드 단위 실시간 알림, 사이트 알림함, 웹 푸시
- 요구가 확인되지 않은 Kafka나 별도 메시징 인프라
- 운영자 개인 블로그

필요성이 실제 트래픽과 운영 요구로 확인되면 각각 별도 ADR로 판단한다.
