# ADR-007 Naver 뉴스 수집원 제거

상태: **Accepted** (2026-09-30). ADR-005의 "뉴스를 수집해 LLM으로 가공한 초안을 자동 게시"하는 현재 구현을 중단한다. 후속 수집원은 별도 ADR로 정한다.

## 변경 기록

- **2026-10-02**: 후속 결정은 [ADR-008](./adr-008-switch-to-learning-platform.md)이다. 다른 뉴스 수집원은 찾지 않는다. Google News RSS는 피드 고지(개인 피드 리더 외 사용 금지)와 robots.txt(`/rss/` 봇 불허)를 다시 확인해 배포 소스에서 뺀다.

## 배경

PostForge는 Naver API HUB 뉴스 검색으로 제목·요약 스니펫을 모아 pgvector에 적재하고, LLM으로 본문을 만들어 `PRODUCT_LAUNCH_NEWS`로 게시했다. 세 가지 문제가 있었다.

1. **약관.** 네이버는 2026-09-07부터 검색 API 데이터를 AI에 입력·학습·노출하는 것, 저장·캐싱하는 것, 가공·재배열해 노출하는 것을 금지했다
   ([뉴스웨이](https://www.newsway.co.kr/news/view?ud=2026090215314059117), [한국데이터경제신문](https://www.dataeconomy.co.kr/news/articleView.html?idxno=42307), [TokenPost](https://www.tokenpost.kr/news/ai/403521)).
   비상업·개인 용도 예외는 없고 유료 API HUB 전환도 같은 약관이다. 기존 이용자 유예는 2027-06-30까지다.
   현재 파이프라인은 저장(pgvector)·AI 입력(초안)·가공 노출(게시) 세 항목에 모두 걸린다. LLM 단계만 빼도 저장과 가공이 남는다.
2. **사실성.** 검색 API는 150~300자 스니펫만 준다. LLM이 그보다 긴 본문을 쓰면 원문에 없는 내용이 들어간다.
3. **저작권.** 뉴스 본문은 저작물이다. 합법 범위(제목·링크·짧은 발췌)로 줄이면 기존 RSS 리더와 차별점이 없고, 차별점을 만들면 침해에 가까워진다.
   면접에서 "저작권은 어떻게 처리했나"에 답할 수 없는 구조였다.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 네이버 유지 + 비상업 | 비상업은 광고·수익 조항만 해제한다. AI 입력·저장·가공 금지는 그대로다. |
| 네이버 결과를 LLM 밖에서 링크로만 노출 | 저장 금지라 조회 시마다 실시간 호출이 필요하고, AI 생성 글 옆에 노출하는 것 자체가 개정 취지와 충돌한다. |
| 언론사 RSS + 짧은 요약 | 약관상 깨끗하지만 RSS 리더와 다를 게 없다. 만들 이유가 없다. |
| Google News RSS | 구글 뉴스 약관(2006)이 개인·비상업, 재포맷 금지, 로봇 수집 금지를 명시한다. 집행 사례가 없을 뿐 허용이 아니다. |
| 기사 본문 크롤링 | 복제·2차적 저작물 작성. 통신사·언론진흥재단 계약은 법인 대상이다. |
| 유료 뉴스 API(NewsCatcher, Perigon 등) | 그들이 긁은 본문에 대한 그들 약관일 뿐 언론사 허락이 아니다. 국내 IT 언론사 커버리지도 얇다. |

## 결정

- `source` 모듈의 Naver 어댑터(`NaverNewsSourceClient`와 프로퍼티·응답·메트릭)와 설정 `source.naver-news.*`, 환경변수 `NAVER_API_HUB_*`·`NAVER_NEWS_ENABLED`, 메트릭 `external_naver_fetch*`를 삭제한다.
- 뉴스 계약(`NewsSourceClient`, `NewsSourceQuery`, `NewsSourceItem`)과 그 위의 수집·선별·초안·게시 흐름은 남기고, 어댑터 자리에 **실험용 Google News RSS 검색 피드 클라이언트**를 둔다. 피드 자체가 개인·비상업 용도로 제한된다고 명시하므로 파이프라인 검증용이며 배포 소스가 아니다. 후속 수집원은 별도 ADR로 정한다.
- `PostReferenceProvider`에 `GOOGLE_NEWS`를 추가하고 `NAVER_NEWS`는 enum 값으로만 남긴다.
- **Flyway 이력을 리셋한다.** 뉴스 도메인을 떠나는 시점을 새 출발로 보고 V0000~V0003을 단일 `V0000` baseline으로 교체했다. 기존 DB는 고쳐 쓰지 않고 지우고 다시 만든다. Naver 유래 게시글·출처 링크·벡터는 이때 함께 폐기되고, 계정은 재가입 또는 `accounts`·`account_roles` 덤프로 옮긴다. 운영 DB 재생성은 다음 배포 때 한다.
- `BoardCategory`를 Google 뉴스 한국판 섹션(대한민국·세계·비즈니스·과학/기술·엔터테인먼트·스포츠·건강)과 1:1로 바꾼다. 수집 섹션 이름이 곧 분야라 매핑 테이블이 필요 없다. 옛 제품 분야(디지털·가전·리빙·뷰티)는 지운다.
- `auth`의 네이버 OAuth 로그인은 검색 API와 무관한 별도 서비스라 유지한다.

## 결과

- 파이프라인(수집 → 선별 → 초안 → 게시 → 데일리)과 모듈 경계는 그대로다. 수집원 교체가 `source` adapter 하나와 설정으로 끝난다는 것이 교체 diff로 확인된다.
